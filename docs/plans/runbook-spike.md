## What you are building (read first)

A prototype that compiles a **runbook** from a guardrail: one host-neutral on-demand skill (`SKILL.md` with `name` and `description`) holding the guardrail's norm, the steps of every procedure whose `operationalizes` lists it, and the facts it is grounded in (`grounded-in` entries that are facts; decisions are named, not inlined). It is generated, committed under `docs/runbooks/<guardrail-id>/SKILL.md`, and a drift check regenerates it in memory and fails when the committed file differs. It is a spike: the commands are `go-getter runbook build <guardrail-id> [--check]`, no pack, nothing written into host skill directories, nothing shipped to adopters.

Pairs to compile (all exist in this repo): `checkpoint-before-gated-action` with `restoring-a-checkpoint` (one guardrail, one procedure); and `branch-names-follow-the-pattern` and `commit-subjects-are-conventional` with `working-a-change` (one procedure operationalizing three guardrails, which tests the many-to-many link: the shared steps must not be copied into three diverging runbooks without the spike saying so).

Working rules: `docs/skills/working-a-change.md`; before every PR run `go-getter:capture`, `go-getter:conform`, `go-getter:attribute`. Guardrails to read first: `one-statement-one-job`, `token-economy`, `neutral-source-has-no-host-specific-language`, `no-runtime-dependencies`.

**Rules the design fixes (do not re-decide):** no fifth artifact type; runbook only (no playbook); generated and committed with a drift check; the spike ends with a go or no-go decision and ships nothing before it.
