## What you are building (read first)

go-getter configures the **agent harness** (the 12 components around a model) and SDLC practices of a project through **host agents** (Claude Code, Codex, Kilo, OpenCode, Cursor, Gemini CLI, Copilot); "harness" never means a host agent (fact 0002). It owns no agent runtime (0015): it compiles neutral source in `src/` to each host's files (0005), enforces rules in tiers — instruction, host hook, git hook and CI (0009, 0025) — and routes work by expected total step cost (0016, 0020). v0.1 is built: foundation plus six harness packs (`context`, `orchestration`, `governance`, `telemetry`, `verification-gate`, `cost-routing`), all adopted by this repo. Read `AGENTS.md`, decision 0068 (this plan's scope), and the guardrails in `docs/guardrails/` before changing code they govern.

**Working rules (interim, until the git workflow pack of v0.3 replaces them — 0068):** never push to `master`; each step is a short-lived `type/slug` branch → PR → squash merge, one git worktree per parallel task (`go-getter worktree new`); Conventional Commit titles with `Refs:` trailers; before every PR run `go-getter:capture`, `go-getter:conform`, `go-getter:attribute`; at each wave boundary run `go-getter:lint`; at release run `go-getter:changelog`. A pack change is only done when this repo has adopted the new pack version (`npm run check:self-adoption`, guardrail `practice-ships-only-after-self-adoption`), `go-getter apply` was re-run and its output committed, and `npm run check:generated` passes. Node ESM, zero runtime dependencies (guardrail `no-runtime-dependencies`).

## Known enforcement debt (carried from the archived plan; wave steps that close an entry say so)

- `context` pack: cache hygiene is tier 1 only (no pre-model-switch event in the hook runtime, 0025); the instruction-file cap covers `AGENTS.md` only.
- `governance` pack: a shell command that merely names a restricted file (e.g. in a `git commit -m` message) is still denied, since commands are tokenised whole (workaround: `git commit -F <file>`); Copilot's tool argument field names are unconfirmed (fact 0031; an unlisted field is scanned); `apply` does not undo a prompt-logging setting when the decision changes; Codex path deny (permission profiles) is not written and may be user-level only, Copilot has no repository-level read deny, and OpenCode and Cursor (except MCP tools) get no output redaction (fact 0031).
- `verification-gate` pack: the stop hook runs only the `implement` checks and reads CI only through `gh` (GitHub Actions); Copilot, Kilo and OpenCode have no blocking stop hook (tier 1); the Codex `Stop` and Cursor `followup_message` shapes are unconfirmed (fact 0023).
- `cost-routing` pack (fact 0025): no Gemini CLI `BeforeModel` router and no Kilo or OpenCode `task` router; the Codex and Cursor rewrite shapes and model values (Cursor's `Task` may take only `fast`), the `<provider>/<model>` format and the Claude Code cache-lifetime keys are unconfirmed; `apply` does not undo cache-lifetime settings and writes no spend caps; calibration has few token records to measure the step shape from (resumed Claude Code sessions only, C.2); the verification stop hook does not re-dispatch a tier up as 0020 describes.
- `telemetry` pack: host OpenTelemetry is written only for Gemini CLI (Claude Code and Codex take it in user config only) and is not undone when the answer changes; the `otlp` answer does not export go-getter's own log; hook events carry tokens and cost only on a resumed Claude Code session (draft 0087).
- Decision 0019's PowerShell shims are not implemented; the runner is POSIX `sh` only.
