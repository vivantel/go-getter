# Work-unit coordination — plan

**Status legend**: `[ ]` pending | `[~]` in progress | `[x]` done | `[!]` blocked | `[>]` moved to another plan. Update a step's marker in the step's own PR; once K2 lands, live state (claim, lease, progress) follows decision 0166 and no `Progress` line is written in git. Written 2026-11-03 from an interview with the repo owner (`sergemso`). Goal: reframe go-getter as a task-solving framework in which humans and agents work thousands of units in parallel, alone and together, with few contradictions, little mutual blocking and little waiting on humans. Product index: `docs/plans/roadmap.md`. Every pending step needs its issue (`Issue: #N`); none exists yet, so create them with `go-getter plan issue` (a human approves each write).

**Read first, in order:** fact `docs/facts/0041-coordination-hotspots-and-contradictions-in-the-current-design.md`; decisions `0165` (the unit), `0166` (claims), `0167` (scope, queue, ids), `0168` (parked asks), `0169` (pull protocol), `0170` (metrics), `0171` (grants), `0172` (validation), `0173` (lifecycle), `0174` (priority, roll-up), `0175` (flags, flakes). All are `draft` until K0. Procedures: `docs/skills/delegating-a-work-unit.md`, `answering-a-parked-ask.md`, `handling-a-failed-or-stalled-unit.md`, `accepting-a-unit.md`. Guardrails to raise to tier 2 as steps land: `work-only-under-a-live-claim`, `a-claim-names-its-holder`, `a-delegated-grant-never-exceeds-its-parent`, `a-change-stays-inside-its-units-scope`, `artifact-ids-have-no-shared-counter`, `a-unit-is-accepted-by-someone-other-than-its-author`, `unit-briefs-are-untrusted-input`. Also read `no-runtime-dependencies`, `owned-files-never-clobbered`, `telemetry-records-metadata-only`, `restricted-paths-denied`.

**Rules the design fixes (do not re-decide):** a plan is the default unit of delegation and one contract serves every level (0165); a claim is an atomic ref with a lease and the tracker holds status, no shared board (0166); scope is declared and enforced, a serial merge queue integrates, ids and indexes have no shared counter (0167); a human ask parks the unit and frees its worker (0168); go-getter defines a pull protocol and runs no fleet, no daemon or server, no new runtime dependency (0169); grants only narrow (0171); the validator is never the author (0172). The code lives in `compiler/src/work/` (new) and `compiler/src/commands/work.mjs` (new); verbs print what they return and keep the library functions pure so the MCP read tools of `mcp-server.md` can reuse them.

**Activation rule:** a guardrail or procedure of this plan stays `draft` until the step that builds the verb or check it names has landed, and is set `active` in that step's pull request, so the generated instruction file never tells an agent to run a verb that does not exist. Guardrails: `work-only-under-a-live-claim` (K2), `a-change-stays-inside-its-units-scope` (K4), `artifact-ids-have-no-shared-counter` (K5, K6), `a-delegated-grant-never-exceeds-its-parent` (K8), `a-unit-is-accepted-by-someone-other-than-its-author` (K10), `a-claim-names-its-holder` and `unit-briefs-are-untrusted-input` (K16). Procedures: `answering-a-parked-ask` (K7), `handling-a-failed-or-stalled-unit` (K9), `accepting-a-unit` (K10), `delegating-a-work-unit` (K17). Run `go-getter apply` in the same pull request.

### K2 Claim, lease, heartbeat, release — [ ]
Class: implement · Effort: high · Needs: K1 · Check: `node --test compiler/test/work-claim.test.mjs`
Context: decision 0166; guardrails `work-only-under-a-live-claim`, `a-claim-names-its-holder`. Git is already the substrate (checkpoints are hidden refs, `compiler/src/checkpoint.mjs`; worktrees, `compiler/src/worktree.mjs`). Work sources are read through `callSource` in `compiler/src/trackers/worksource.mjs`; tracker writes follow the project's answer (decision 0160, guardrail `tracker-writes-follow-the-answer`) and only through the `plan issue` verbs. No new runtime dependency.
Do: add `compiler/src/work/claim.mjs` and `go-getter work claim|heartbeat|release <unit>`. A claim creates `refs/go-getter/claims/<file-stem>/<local-id>` on the remote by an atomic push that fails if the ref exists; its content records holder kind (`human|agent|ci`) and id, the `created` time, lease expiry, brief version (a hash of the unit's text) and last heartbeat. After creating its ref the claimant re-reads the claim refs and, if an earlier overlapping claim exists (same unit, ancestor or descendant, or overlapping scope; earlier by `created` then holder id), deletes its own and reports itself queued (decision 0166 item 1, 0167). A claim covers its unit's subtree; a descendant is claimed only as a delegation by the ancestor's holder. The lease depends on holder kind (pack answers `lease-agent` 60 min, `lease-ci` the job's limit, `lease-human` 8 h) and is renewed by `heartbeat`, by every `go-getter` verb and by the generated pre-commit and pre-push git hooks; a unit with live children has no lease; a parked unit holds a non-expiring `parked` state. A state change (claimed, released, expired) posts one comment on the unit's issue when tracker writes allow it; heartbeats never touch the tracker or the working tree. With the pack answer `require-claims` on (default off) `ship` refuses a branch whose unit has no live claim held by the caller. Without a remote, fall back to a local ref and say so. Make `go-getter plan status` compute a unit's state from the ref and merged state, not from a marker alone. Add the three pack answers in `src/packs/orchestration/` (`docs/skills/adding-a-practice-pack.md`) and regenerate with `go-getter apply`.
Done-when: tests with a temporary bare remote show two concurrent claimants with exactly one keeping the claim (including overlapping scopes, and an ancestor and a descendant claimed at once), a heartbeat extending the lease, a verb or a commit renewing it, an expired lease taken over, a parent with live children never expiring, a parked claim never expiring, a release freeing the unit, the holder recorded, heartbeats creating no tracker call and no working-tree change, `ship` refusing an unclaimed branch only when `require-claims` is on, and a missing remote falling back and saying so; `npm run check:generated` passes.
