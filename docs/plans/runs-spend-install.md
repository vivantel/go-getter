### R4 Remove the human-only start: authority comes from the approved plan — [x]
Class: plan · Effort: high · Needs: none · Human: the owner accepts the superseding decision (it amends item 1 of 0130 and replaces drafts 0137 and 0184) · Check: `npm run check:plans && npm run check:guardrails`
Context: today `run start` is denied to every agent, so no run can start from the conversation. A human-only start serializes every actor behind one person, which contradicts the aim of many humans and agents working in parallel (0165, 0169) and 0155 (human attention goes to plan approval, four ask-triggers and batched releases). Authority already has a source: the owner approves a plan once (`plan approve`, T9), and the project's `run-grants` answer (0135: `git-push, pr-create, pr-merge, pr-close`) names what steps of an approved plan may do without asking; 0130 item 4 excludes force-push, history rewrite, settings, tags and releases, and 0171 says grants only narrow. A first attempt, branch `feat/run-start-by-request` (draft 0184), reads the person's last chat message from the host transcript: it works only where a transcript exists, and a forged line defeats it. Do not ship it.
Do: gate effects, not starting. Any actor may start or claim work on a step of an approved plan; the run record is created by the CLI from the plan's approval and the `run-grants` answer and is the grant, never wider. A plan with no approval starts nothing. The time limit, spend cap (refuse to start when a cap is set and spend is not recorded) and the per-use preconditions of 0130 item 3 bound it. `--grant`, `approvals *`, `plan approve`, releases and tags stay human-only. Supersede drafts 0137 and 0184 with one decision that amends 0130 item 1. Update the `autonomous-run` skill and INSTALLING.md.
Done-when: tests show an agent starting work on a step of an approved plan with no typed command and no extra prompt, an unapproved plan starting nothing, `--grant` and a widening answer refused, a start refused without a time limit or with an unbound spend cap, the record unwritable by an agent, and a hook test per host; the decision is accepted by the owner.
Result 2026-11-04 · all done-when items are met; decision 0186 (`docs/decisions/0186-*.md`) accepted by the owner. The hook allows an agent's `run start <plan> [--through N] [--hours H]` on an approved plan (`agentStartRefusal` in `compiler/src/hook.mjs`); `plan approve` now also adds the Approval line to an existing plan; `run start` refuses a pending plan and records the approval text; tests in `compiler/test/run-start-approved.test.mjs`.
