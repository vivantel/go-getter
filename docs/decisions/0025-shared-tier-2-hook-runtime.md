## Decision

Host hook configs generated by `apply` all invoke `.go-getter/bin/go-getter hook <event> --host <id>`. The runtime (`compiler/src/hook.mjs`) evaluates the project's tier-2 guardrail entries once, in Node, and only the answer format differs per host (exit 2 with a reason, or Copilot's JSON decision). Events today: `pre-tool` (tier-2 guardrails, builtin `deny-path`) and `session-start` (capture and lint nudges).

## Why

Six hosts with different hook schemas would otherwise need six implementations of every rule; one runtime keeps rule logic single-sourced (0005) and testable, and inherits fail-open behaviour from the runner (0019).

## Tradeoffs considered

- **Translate rules into native permissions per host** (e.g. a path deny list in a settings file): no process spawn per tool call, but each rule kind needs a translator per host and several hosts lack an equivalent.
- **Cost accepted**: one Node process per hooked tool call; payload fields are host-specific, so path extraction is heuristic (all string values of the tool input).
